# 共享目录账户同步

1. 在 macOS 的 iCloud Drive 或已有 OneDrive / NAS 中准备一个 Quota 文件夹。Windows 使用对应客户端实际可访问的同一文件夹；没有 iCloud 客户端也可以使用 OneDrive。Quota 不创建账号、不猜测目录。
2. 各设备打开「设置 → 跨设备同步 → 选择目录」，选择该同一目录，开启「同步账户展示资料」。Token 活动沿用相同目录。
3. 点击「立即同步账户」。账户后台每 5 分钟合并，与 Token 自动采集开关独立；应用退出时停止。共享文件是否已上传/下载以云盘客户端为准。活动页「立即同步」同时尝试账户合并。

## 安全范围

账户文件位于共享目录的 `quota-accounts-v1/<设备 UUID>.json`。只序列化固定类型字段：账户 UUID、平台、名称、创建时间、同步方式、提醒阈值、手动金额/预算，以及结构化余额、分项金额和订阅额度快照。分项名称由固定枚举生成，订阅套餐名称归一化；不传自由格式供应商文本。

订阅的手动/备用额度支持 `%` 与 Credits；百分比为 0–100，未填写与 0 分开保留。即使自动订阅没有填写备用额度，表单保存的 `%` 单位也不会阻断账户同步。累计充值与累计消费仍只接受支持的货币或 Credits，不能使用百分比。使用百分比的设备需升级到 1.0.1001 或更新版本，旧版共享校验不支持该单位。

**共享文件没有任何密钥类型字段**：共享文件交换不读取系统凭据库，不同步 API Key、AccessKey、管理员密钥、Cookie、Codex token 或账号绑定信息；也不传备注、URL、请求头/请求体、自定义接口解析配置、原始响应、对话正文或源日志。不要在账户名称、设备名称中填写秘密。同步文件包含账户金额等个人资料，请使用仅本人/可信设备可访问的目录，不公开分享。

新设备收到的是展示资料和快照，不具备查询权限。需要查询时在该设备连接账户；原设备的自定义连接字段与系统凭据不被远端覆盖。备份的加密登录信息选项属于用户主动导出，不会被自动同步程序扫描或上传。

## 合并与故障

- 本机启动和同步前自动恢复已确认关联下失联的凭据，并在同平台、同连接配置且登录信息完全匹配时自动整理重复卡片。原凭据保留，现有不同登录不会覆盖或混合；凭据写入和核验失败时不移除原卡片。
- 同平台但身份未知的远端 UUID 保留在后台，不自动新增卡片或混入当前余额。用户无需逐条选择 UUID；确实需要另一个独立账户时，可在设置折叠项「其他设备的额外账户」中点「显示此账户」。独立账户决定持久保留。
- 凭据恢复仅在本机系统凭据库内进行。启动会修复 1.0.1401 遗留的已关联 UUID：补齐保留账户缺少的 API Key、Cookie 或其他登录字段。已有不同凭据优先保留，AccessKey 必须成对处理。自动身份比较只针对本机已保存账户，不读取未知远端 UUID 的密钥，不上传密钥、Cookie 或它们的散列。
- 同账户 UUID 的显示资料以最新本机观察到的编辑时间为准；同毫秒冲突按设备 UUID 排序，确定性收敛。独立新增的账户 UUID 不同，不根据相同名称猜测为同一账号。首次同步已有同 UUID 账户时，较晚加入同步的显示资料可能成为最新编辑。
- 余额/订阅快照独立比较查询时间，旧值不覆盖新值，不相加。金额 0 与无数据区分；云端快照不能当成刚查询的实时账单。
- 删除仅影响本机，删除当下即在本机同步台账中标记隐藏（无需等下一轮同步），避免下一轮重新出现；不删除其他设备账户或任何远端文件。账户 UUID 和隐藏台账不要手动修改。导入同 UUID 的账户可重新启用本机显示。
- 设备时钟应正确；超过当前时间一天的编辑或快照被拒绝。未知字段、跨平台同 ID 冲突、无效格式和超过 4 MB / 1000 账户 / 100 设备文件的输入不合并。同步文件子目录/文件不读取符号链接。
- 本机 `account-sync-state.json` 保存已观察的安全资料版本、隐藏记录、待确认项、独立账户决定及本机关联映射，`account-sync-status.json` 保存最后本机合并时间和错误。失败保留本机账户及待重试版本；云盘未下载完成或目录离线时可稍后重试。配置与台账是两个文件，部分写入失败后会重新比较，不保证跨文件事务。

当前共享同步不包含余额历史、应用全局设置、模型资料或登录信息；这些内容仍通过统一备份/导入迁移。上线前的测试使用合成共享目录，不声称已经验证 iCloud / OneDrive 的真实云端传输。

修复版 1.0.1402 保持 v1 共享格式，关联映射仅保存本机。两台设备均应更新，启动即可恢复之前确认的关联及本机凭据；不再要求逐条选择保留账户。没有本机登录的新设备仍需首次连接服务商。

1.0.1504 补回 1.0.1401/1402 的本机台账兼容和关联处理。升级时直接读取既有 pending、independent、links，不删除或重置台账；更早台账中缺失的字段使用默认值。共享包继续使用严格的 v1 白名单，未知字段仍拒绝。设置页在后台同步完成后刷新状态，成功会清除旧异常。


## 1.0.1600：关联一次，多设备生效

所有设备更新到 1.0.1600 后，选择同一共享目录。若同一账号出现不同记录，在「设置 → 账户关联与额外账户」选择该账号的本机账户，再点击「关联为同一账户」。仅确认确实是同一个账号；同平台的不同账号选择「保留为独立账户」。已确认关联会随下次成功同步传到其他设备；操作入口会立即尝试同步。

共享关联使用独立的 `quota-account-links-v1/<设备 UUID>.json`，只含 schema、设备 UUID 和 source/target/provider 三个字段的关联记录，不含登录信息、登录信息散列或会话引用。关联按无向连通分组确定逻辑身份，保留每台电脑原有本机 UUID、连接配置及凭据条目；显示资料和快照路由到保留账户，金额不相加。设备收到关联不读取未知远端 UUID 的凭据、不从远端身份推断登录。

已学到的关联在本机持久保存并转发，因此另一台设备离线、文件暂未下载或只剩旧 v1 账户文件时，不会重新要求关联。同平台不同名称不自动合并；本机两个账户存在不同登录，或已明确决定独立时，冲突会报告并保留本机账户。账户删除仍为本机隐藏，不远程删除其他设备。

旧 v1 账户文件保持不变，旧版会忽略新关联目录；要获得一次关联的效果，所有参与设备都应升级。本机台账新增 shared_links 和 associations（严格固定类型），不可直接用旧版覆盖安装后读取新台账。共享目录是用户信任的来源，保护其访问权限。
