# Token 活动与跨设备同步

在「Token 活动」点击「立即同步」，首次扫描本机保留的 Codex 和智谱 ZCode 历史。打开 Quota 后默认每 30 秒增量采集；在「设置 → Token 活动」选择 5 秒、15 秒、30 秒、1 分钟、5 分钟或 15 分钟，也可关闭自动采集。完成采集后活动页自动刷新。更短间隔会增加本机扫描负担，不保证上游日志即时写入。

共享目录交换仍按每 5 分钟的最小间隔随采集执行；采集频率超过 5 分钟时，交换随下一次采集执行。「立即同步」不受此节流限制。Quota 退出或电脑休眠时不会采集。ZCode 的任务索引库不包含用量，因此跳过该库，仅从实际用量库读取指标；未知用量结构仍报告兼容错误。

跨设备：在每台设备的「设置 → 跨设备同步」或活动页「同步设置 → 共享目录」选择各设备都能访问的同一个 iCloud Drive、OneDrive 文件夹或 NAS。目录传输由对应客户端完成；Quota 不创建云账户、不上传登录信息。账户展示资料规则见 [账户同步](account-sync.md)。各设备需运行 Quota 才会采集和交换记录。未选择目录时只在本机统计。

## 数据与口径

- Codex：只读 `CODEX_HOME`（默认 `~/.codex`）下 `sessions`、`archived_sessions` 的 JSONL。按累积 Token 的增量计数；工具按 call ID 去重；分叉继承的历史不重新计数。
- ZCode：只读 `~/.zcode/v2/tasks-index.sqlite` 和 `~/.zcode/cli/db/db.sqlite`，优先采用 `model_usage` / `tool_usage`。旧记录从 message/part 中只选取用量字段，排除已有的现代用量记录。迁移产生的两份数据库按请求 ID、尝试号与工具 call ID 去重。
- 兼容其他设备共享的 Trae 指标，按相同的事件 ID 去重并保留来源；本版不扫描 Trae 原始日志。来源选择中的「Trae（同步记录）」只展示已同步的指标。
- 输入包含缓存命中和写入；推理包含在输出中。总量不再叠加这些子项。请求尝试分别记录，因为每次尝试可能产生实际用量。
- 历史范围只覆盖仍保留在本地的记录，无法恢复已删除的会话或厂商未记录的用量。这是用量统计，不代表账单或订阅剩余额度。
- 每台设备有独立 UUID 和可编辑名称；全部设备合并后可以按设备、来源和时间筛选。相同日志被复制到多设备时只保留一笔，确定性归属 UUID 较小的设备，不宣称能够还原原始执行设备。

### Codex 用量不更新时

先区分 SSH 的使用方式：本机 Codex 会话只是调用 `ssh` 工具命令时，读取本机日志；在 Codex 桌面端添加或选择 SSH 远程主机，或先 SSH 登录再在虚拟机内启动 Codex CLI 时，需检查远程运行环境中的日志。[OpenAI 官方远程连接说明](https://learn.chatgpt.com/docs/remote-connections#connect-to-an-ssh-host)确认桌面端会通过 SSH 在远程主机启动 Codex app server。界面在 Windows 不代表会话也在 Windows 执行。Quota 1.0.1900 的采集器只扫描已配置的本机目录，不会通过 Codex 的 SSH 连接读取远程会话；仅同步 Quota 的云盘目录也不会产生尚未采集的远程指标。

远程日志若已通过现有工具同步或挂载到本机，可在「Token 活动 → 采集设置 → 日志位置」选择包含 `sessions` / `archived_sessions` 的根目录后手动采集。完整 JSONL 可能包含对话，应用只提取用量字段；原始日志的转移应留在用户控制的设备内，无需复制 `auth.json`。远程历史能否补采以源会话仍保留有效 Token 记录为准，不保证恢复已删除或上游未写入的用量。

1.0.2100 新增可选的 **Ubuntu SSH 用量采集**（1.0.1900 本身不具备此入口）。远程登录 shell 中读取 `CODEX_HOME`，未设置时使用 `~/.codex`；自定义目录填写 Ubuntu 绝对路径。本机日志仍同时采集。

1.0.2300 起，在「Token 活动 → 采集设置 → SSH 设备」点击「识别设备」，再按设备勾选需要纳入统计的对象并保存。新设备默认不勾选，也可全部不选；同一设备的多个别名按机器标识、远程用户及真实 Codex 目录合并。打开设置仅静态读取本机 OpenSSH 配置的字面量 `Host`（支持 `Include`、引号和等号）；点击识别才建立 SSH 连接，仅读取设备标识，不扫描日志。识别上限为 32 个连接，每连接最多 10 秒、并发 4 个。仅勾选并保存的设备会读取用量，仍可手动添加连接。

取消勾选会停止该设备采集，并让已有用量退出 Token 活动、我的使用（包括实际价格分母）及悬浮窗汇总。指标和同步记录保留，重新勾选恢复；选择仅作用于当前 Quota 主机，不同步排除其他客户端。旧单主机设置保留启用状态，首次识别或采集后绑定设备 ID；明确保存空列表不会重新启用旧主机。设备离线保留已保存选择，别名改指向另一设备时需重新识别选择，不将其用量静默算入原设备。

静态发现配置不调用 SSH、不执行 `Match exec` 或 `ProxyCommand`、不读取私钥，不按通配符猜测主机、不扫描网络；后续识别设备和采集实际调用 SSH，由 OpenSSH 使用已有连接配置。Windows 用户配置为 `%USERPROFILE%\.ssh\config`、系统配置为 `%ProgramData%\ssh\ssh_config`；其他系统使用用户配置及 `/etc/ssh/ssh_config`。限制为每文件 256 KiB、总计 4 MiB、128 文件、8 层 Include、128 主机；循环、动态路径/递归通配符、编码和权限问题会显示提示，保留手动入口。仅存于 Codex 内部且未写入 OpenSSH 配置的连接，以及仅有 `known_hosts` 记录的设备，不能据此推断登录别名、用户和端口。

配置语义依据 [OpenSSH ssh_config 手册](https://man.openbsd.org/ssh_config)，发现列表仅表示本机存在配置，设备识别验证身份，远程日志是否存在和可读仍在勾选保存后采集时验证。隔离解析检查：`cargo run --release --example ssh_discovery_checks`；设备合并选择检查：`node scripts/verify-ssh-devices.cjs`。

远程需 Python 3.7 或更新版本，本机需 OpenSSH 客户端；复用已配置的密钥、SSH agent 和 `known_hosts`。不弹出密码输入，不自动接受主机密钥，不复制、保存或刷新 SSH/Codex 凭据。连接及读取超过 25 秒会终止本轮 SSH 客户端并报告错误，本机已采集的指标保留。

远程脚本只读源日志，返回白名单投影：会话标识、继承边界、模型、时间、累积 Token 字段、工具名称和去重摘要。不返回对话、提示词、工具参数、环境变量、认证文件或原始 JSONL，也不在远程写脚本或账本。完整计数对象只在远程生成摘要，以保持与原有本机事件 ID 一致，新增未知字段不会经由投影外传。Rust 端沿用现有增量解析器，指标与游标逐文件原子提交到 `activity.sqlite`；失败文件不推进游标。

历史分批补采，每轮最多 4000 条投影、扫描最多 128 MiB，响应最多 16 MiB。活动页持续显示补采或失败状态；重复采集、复制日志、别名切换和本机/远程同一事件不会重复计数。远程设备 ID 根据机器标识、用户及数据目录确定，别名变化不会改变归属；复制日志依然遵守现有 UUID 较小者归属规则。远程指标沿用已有云盘同步格式，旧客户端能汇总，但未收到远程设备描述时可能不提供对应设备筛选；新版为未知来源设备保留可选的通用设备名。

隔离回归：`cargo run --release --example ssh_activity_checks -- <Python可执行文件>`。该程序执行真实投影脚本与入库链路，验证字段白名单、本机事件 ID 一致性、追加、未完成行、截断、别名和日志复制去重、失败游标回滚、历史分页与跨设备汇总，不连接真实 SSH 主机。真实主机的网络、登录 shell、SSH 认证及 Python 环境需另行验证，不能把合成回归称为真实 SSH 验收。

已保存的 `codexHome` 是固定目录；更改环境变量 `CODEX_HOME` 不会覆盖它。本机桌面端和 CLI 若使用不同数据根目录，当前单个路径设置只能采集其中一处。先核对实际运行位置及目录，再检查自动采集开关、设备/模型/日期筛选和最近采集详情，不因一次图表不变就删除 `activity.sqlite` 或重置游标。

采集器对每份 Codex 会话独立提交指标和游标：单份文件无法读取或存在无效指标时保留该文件原游标、下次重试，并继续采集其他会话。目录缺失、为空、枚举失败或单份采集失败会进入最近采集详情。局部失败不阻断 ZCode、Harness 和共享目录同步。

只读诊断：在出问题的 Windows 上运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/diagnose-codex-activity.ps1`。自定义 Quota 配置目录可传 `-QuotaDataDir <绝对路径>`。脚本只输出采集设置、最近状态和日志元数据；最多检查最新五份日志各末尾 2 MiB 中的用量字段，不输出对话、工具参数或认证文件。样本未找到 Token 不代表整份日志没有 Token，Windows 未关闭的文件修改时间也可能滞后，应结合最后 Token 时间判断。脚本不修改源日志、统计库或个人配置。

## 热力图、模型与时间量程

模型按钮和明细中的模型名称可选中该模型，顶部指标、每日热力图、趋势与其他明细都按模型名称精确筛选。模型切换选项保留当前设备、来源及时间范围内的所有型号；不会把相似型号合并。未知品牌使用字母标识，已支持品牌复用账户图标。

热力图按当日总 Token 与当前图内峰值分为四档，零用量使用中性色；点击日期查看输入、输出及缓存子项。支持方向键移动和 Home/End。近 N 天包含今天及首日完整的本地自然日，空日期补零；全部历史可按年份浏览热力图，趋势保留整个历史范围。未来日期不参与当前报表，原始指标仍保留在统计库中。

日量程为折线，周/月为汇总柱图；周一开始一周，月按自然月划分，范围两端可能是不完整周或月。按周期只汇总 Token 字段，不把每日会话数相加伪造唯一会话数。缓存与推理继续作为子项，不叠加到总量。

图表计算与静态组件检查：`node scripts/verify-activity-charts.cjs`、`node scripts/verify-ui-render.cjs`。这些不代替真实浏览器的布局和键盘交互验收。

## 存储与同步协议

`%APPDATA%\Quota\activity.sqlite` 保存指标、增量游标、同步队列及已接收文件记录；`activity-settings.json` 保存日志路径、设备与同步设置；`activity-status.json` 保存最近采集状态。`QUOTA_DATA_DIR` 可用于隔离验证。

共享目录的 `quota-activity-v1/<设备 UUID>/` 保存只包含指标的版本 1 分片。1.0.1500 起新包为 `.json.zst`，使用 Zstandard 无损压缩；读取同时兼容旧 `.json`。每包仍最多 1000 条、解压后最多 4 MB，不改变事件 ID、结算修订号、日期和统计精度。写入采用临时文件、落盘与原子替换；成功写出后才移除队列。同步队列按事件 ID 合并，更新同一结算不会不断增加重复项。重新接收或扫描相同事件不会重复累计。同步内容没有对话正文、工具参数、API Key、Cookie 或登录 Token；会话 ID、模型名称、工具名称、时间及设备名称会随指标同步。共享目录应使用用户自己的访问权限。

在「设置 → 跨设备同步 → Token 同步空间」查看文件大小并优化旧文件。**所有同步设备必须先升级到支持压缩包的版本，旧版无法读取新压缩包。** 确认升级后，每台设备只压缩自己 UUID 目录中的旧包，逐包回读比较完整内容再移除原 JSON；损坏或归属不一致的文件保留。中途退出可能同时留下两种格式，重试安全且不会重复统计。其他设备的文件需要在对应设备分别优化；这里显示的是文件内容字节数，云盘历史版本、回收站和文件系统分配空间由云盘/系统管理。手动 JSON 导出与导入保持原格式。

空间验证：`cargo run --release --example sync_storage_checks`；传入现有 `quota-activity-v1` 的绝对路径时，会复制到 `target` 下的隔离副本，测量压缩空间并比对总量、各 Token 子项、模型/设备汇总、工具调用与会话，不修改原共享目录。

## 1.0.1600 混合版本同步

共享目录每个设备发布 `reader.capability`（旧版不会作为统计包读取）。发现其他设备未确认压缩读取能力时，新版自动恢复本机已压缩包的逐字节 JSON 兼容副本，并保留压缩原包，旧版仍可读取 `.json`。兼容期空间会增加；全部设备升级到 1.0.1600 并各同步一次后停止新建副本，才允许优化本机旧 JSON。设备 UUID 不合并，也不改写其他设备目录。暂时离线或损坏的单包保留重试，不阻断其他有效文件；接收回执改为解压内容指纹，同名文件变化不漏读。设置中「重新读取共享数据」清除接收回执，保留指标并按事件 ID 去重。

## 模型使用价格（1.0.1600）

以厂商为主，展开显示具体模型与运行档位用量。实际价格 = `(已记录订阅费 + 对应周期按量实际消费) / 对应日期实际 Token × 1,000,000`。费用周期必须完整落入筛选范围，未有费用记录的日期不进入分母；多周期取并集，跨币种分别计算对应周期用量。缓存和推理是 Token 子项，不重复加入总量。没有费用、零费用、没有用量分别处理，未知不能当作零。

公开订阅套餐只在官方来源核实后提供，并展示来源、核实时间、地区与周期；选择后需确认实际订阅开始日。月付、年付按完整周期与整期金额保存，修改金额即按实付处理。进行中周期以全额订阅費除以截至当前采集的 Token，均价随使用变化。多账户支出需用户核对，订阅其他功能也共享费用；具体模型只显示用量，不伪造逐型号结算。原 API 资料等值估算不再作为此页实际支出。

`vendor-costs.json` 本机原子保存按厂商/日期/币种的支出及账户累计充值/消费快照。相同范围更新，重叠同币种范围拒绝，避免重复算钱；支持清除记录。接口已有累计充值/消费可从账户展示快照恢复，今后保存金额变化与最新未变采样，避免每次刷新增加记录。计数重置、缺值、币种变化不推算消费差值。旧 `balance_history.json` 的上涨/下降只标作核对参考，不当确认付款记录；旧版未保存的充值流水不能凭空恢复。`usage-prices.json` 的旧数据保留兼容，本页不删除，发布当时新的支出文件仅本机保存；1.0.1900 起加入下述费用同步，备份协议不变。

验证：`cargo run --release --example vendor_cost_checks` 与 `node scripts/verify-vendor-costs.cjs`。
验证：`cargo run --release --example activity_checks` 覆盖重复计数、追加、未完整行、截断重读、分叉、双设备、筛选和重复 ZCode 数据库；`--live` 在独立测试目录只读扫描本机来源，不修改原日志和个人 Quota 配置。

官方 ZCode 功能说明：[Usage Statistics](https://zcode.z.ai/cn/docs/usage-stats)。这里展示本地活动，与厂商 Coding Plan 云端额度分别计算。
## DeepSeek Harness 适配（2026-10-04）

在 Token 活动的「同步设置 → 日志位置」选择 Harness 的持久化根目录。未选择时不扫描；不推测默认目录。支持官方 v0 至 v4（1.0.1900 补充 v0/v1），含 `session.v2.jsonl` 至 `session.v4.jsonl`，以及默认 `.jsonl.zstd` 的拼接压缩帧。每个会话只读取最高编号的代际；未知版本不回退到旧版，不修改或迁移源日志。

仅保存会话标识、时间、模型、Agent 标签、工具名称和用量。顶层 `usage` 优先，否则取嵌入 stream 的最后一个 usage。Harness 的非缓存输入、缓存读、缓存写互斥，三者组成输入总量；推理是输出子项。`llm/retry-started` 分隔计费尝试，同一尝试的后续结算替换旧样本。同步使用结算序号 `revision`，较旧副本不能恢复被修正的旧计数。分叉会话跳过最后一个带 `inherited: true` 的 `session/end-seed` 及之前记录，避免复制历史重复统计。

只采集完整 JSONL 行；压缩流末尾不完整时保留已解出的完整记录，完整帧损坏则报告错误。单个源文件/解压内容上限 256 MB、单行上限 32 MB、最大递归 12 层，不跟随符号链接。1.0.1900 起兼容旧 v0/v1：`session.jsonl[.zstd]` 与 `session.v1.jsonl[.zstd]`。旧版 `seedLength` 按逻辑序号跳过继承记录，打包文本/推理/工具参数行只检查序号范围，不保存或展开内容；用量读取 `assistant/chunk` 中最后一条 usage，并由同次请求的最终结算替换。

Harness 重试用递增尝试编号标识，不再依赖格式迁移会改写的物理序号；结算修订号同时包含格式代际。同一会话从 v0/v1 升至 v2–v4 后仍只算一次。`harnessIdentity: 1` 表示新统计标识；首次采集会重读既有 Harness 日志、替换同一会话的旧标识，接收到旧云包时不会恢复已替换计数。请将参与 Harness 统计的设备都更新至 1.0.1900；旧客户端不理解这次标识迁移。未适配的新版本仍拒绝回退，并在错误中显示实际版本号。

依据：[官方持久化格式](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/session/session-persistence-jsonl)、[官方用量折叠](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/token-meter/src/usage-projection.ts)。验证命令：`cargo run --release --example harness_checks`。

## Trae 本机用量（1.0.1500）

在 Token 活动的「同步设置」连接本机 Trae 并保存，首次连接需打开 Trae 或 Trae SOLO。默认不连接。Windows 会仅从加载 `ai_agent.dll` 的 Trae 进程只读获取本地 SQLCipher 数据库密钥，经页面 HMAC 验证后存入 `Quota` 系统凭据管理器；不读取或同步登录令牌。已连接后，即使 Trae 退出也能读取保留的历史。

自动识别 `%APPDATA%/Trae CN`、`TRAE SOLO CN`、`Trae` 和 `TRAE SOLO` 的 `ModularData/ai-agent/database.db`。日志位置可指定应用数据目录或包含 `database.db` 的目录。只读获取文件及 WAL 的稳定快照，只使用校验通过的完整已提交事务，数据库只在内存解密，不创建解密数据库文件。

只选择 `chat_turn` 的会话/轮次标识、创建和更新时间、`context.token_usage` 与 `context.persist_user_message_context.model_info`；不落库对话正文、工具参数、项目路径或密钥。输入使用本地 `prompt_tokens`，输出使用 `completion_tokens`，缓存和推理是子项，不叠加到总量；这些是 Trae 本地保留的轮次统计，不等同于服务端每次内部调用、积分账单或订阅剩余额度。当前不采集 Trae 工具调用。来源筛选为「Trae」。

事件按会话和轮次标识全局去重，复制数据库不重复计算，结算更正以 `updated_at` 的 revision 为准；同一来源错误不阻断其他来源。跨设备同步仅交换已有指标，各设备需升级到支持 Trae 的 Quota 才能接收该来源。未知表结构、用量口径或页面校验失败时不猜测数字，保留已有统计。

采集或同步的非阻断问题改为短暂提醒；同一错误只提醒一次，刷新、切页和重启不重复弹出。只在本机界面存储错误指纹，不保存错误正文；原始问题仍在「同步设置 → 最近采集详情」按不同消息去重展示。

验证：`cargo run --release --example trae_checks` 检查真实 WAL、未完整尾部、校验失败、重复/复制/同步去重、下调结算、隐私与旧设置迁移；`--live` 仅在独立统计目录读取本机来源。参考格式：[Trae SQLCipher 4 数据库与用量字段](https://github.com/Oh-My-Trae/trae-db-decrypt)。

### Trae 提供与 API 接入的区分（1.0.1501）

Trae 的模型列表既包含它自己提供的模型，也包含用户自行接入的模型，两者的费用来源不同：前者消耗 Trae 订阅额度，后者消耗用户自己的厂商账户。每个 Trae 轮次按 `model_info` 中已有的确定性标记归入一条通道：

- `config_source` 不为 1，或 `is_preset` 为 false，或带有自己的请求地址/密钥（`base_url`、`ak`、`sk` 任一非空）→ **API 接入**（`api`）。
- 否则 `is_preset` 为 true 或 `config_source` 为 1 → **Trae 提供**（`trae`）。
- 没有任何标记 → 保持**未鉴别**（空值），不猜测为任意一侧。

只读取上述布尔事实；请求地址、密钥和会话令牌一律不落库、不进日志、不同步。模型名优先取 `config_name`，为空时依次回退 `display_model_name`、`model_name`，仍为空才记为「未知模型」（此前空字符串会被当成模型名，导致这部分用量无法识别）。

界面上，Trae 在「供应商汇总」中独立显示，vendor:trae 包含全部 Trae 来源；「Trae 提供」「API 接入 Trae」和「未鉴别通道」分别使用 channel:trae、channel:api、channel:unknown。厂商和普通模型筛选仅含非 Trae 来源，避免同名模型混算。选择 Trae 后自动显示通道明细；模型选择器和模型明细不列出 Trae 内部模型名，缓存面板按通道汇总。全部用量仍包含所有来源。

内部模型行继续以不可见分隔符携带通道，旧 Trae 记录的空通道在报表键中标为 unknown，原始记录不变。下次采集仍按 revision 补全，不猜测来源。
验证：`cargo run --release --example trae_checks` 覆盖标记归类、空模型名回退、通道筛选与「地址与密钥不落库」；`--live` 在独立统计目录只读扫描本机 Trae，并断言每个真实轮次都能归入 Trae 提供或 API 接入。

厂商分类仅列出非 Trae 来源的模型。Trae 作为独立供应商提供全部用量和各通道汇总入口，其内部模型不会产生官方厂商选项；同名官方模型仍正常显示并独立统计。

## 我的使用云盘同步（1.0.1900）

继续复用设置中的共享目录，不再采集、保存或上传第二份 Token 活动。`quota-activity-v1` 负责全部已有用量；新增 `quota-usage-v1/<设备 UUID>.json` 只交换订阅/按量支出账期、按账户 UUID 去重的累计充值/消费观察快照、固定月度参考汇率。账户名称及关联继续使用原账户协议，费用包不含名称、端点、密钥、Cookie、对话或工具参数。费用快照按显式账户关联汇总，仅用于计数差值，不能自动当作实付账单；余额变化参考仍取各设备本机余额历史。

两个离线设备创建了不同键但日期重叠的同厂商/币种账期时，保留本机账期，拒绝这一包的账期合并并显示冲突日期；其他有效包、汇率和财务快照继续处理。在原设备编辑或删除其中一个冲突账期后再次同步即可恢复。每包上限 8 MiB、最多 100 台设备、10,000 个账期及汇率修订（含删除）、50,000 条财务快照；不读取符号链接，损坏/未知字段不覆盖本机记录，下一次会重试。

开启同步后，手动更新“我的使用”或设置中的“立即同步”会一起交换数据；应用运行时约每 5 分钟自动交换，关闭自动采集仍继续同步。另一端需同样升级，选择相同的云盘文件夹；旧版忽略新费用目录。`usage_sync_checks` 用隔离目录模拟两台设备，覆盖新增、同键竞争、删除、旧快照、账期移动、重叠冲突及损坏恢复；不读取个人数据，不声称已完成真实跨设备云盘传输。
