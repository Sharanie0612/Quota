# 1.0.3401 主窗口玻璃方框与直角高光修复

2026-10-31，Windows 本地修复构建。展示版本与包版本均为 `1.0.3401`。

用户反馈主窗口内出现奇怪方框。本轮在同一安装程序的隔离 WebView 中复现了背板重复合成产生的矩形增白区域；该现象尚不能代替用户所见方框的逐处人工确认。

## 原因与修复

主窗口已由 Windows Acrylic 提供原生材质，网页根层透明。工具栏、导航和分段控件再使用 `backdrop-filter` 时，会把已有半透明网页像素重新合成一次，形成额外的矩形色层。

在实际安装版 `1.0.3400`、WebView2 `156.0.4314.50` 的空账户隔离资料中，工具栏空白处背景 Alpha 为 47，薄色层 Alpha 为 38。按一次 source-over 合成应为 78，实际为 111，多出 33；仅关闭网页背板滤镜后同点回到 78。新回归脚本运行旧安装版时按预期失败，原始记录保留。

原生材质成功时，主窗口的这些控件使用单一薄色层与边缘高光，不再做第二次网页背板滤镜。透明主窗口、Windows Acrylic、指针及键盘高光继续保留。原生材质失败时仍恢复可读实底，并在该实底上保留 CSS 折射。任务悬浮窗未改动。

用户补充鼠标移动或点击时出现直角边框。另在浏览器与同一包版本的隔离原生中间构建中复现：工具栏高光继承到的圆角为 `0px`。中间构建已通过十组透明合成像素，仍被新增悬停圆角检查拒绝，未安装交付。修复后工具栏与高光共同继承工作区圆角；新增悬停、点击、移出后的中心和四角像素检查，避免保留直角框或高光残留。

网页滤镜处理的是网页背板，不包含桌面原生材质。参考 [Microsoft WebView2 透明背景讨论](https://github.com/MicrosoftEdge/WebView2Feedback/issues/4945) 与 [Filter Effects 2 编辑草案的过滤及合成步骤](https://drafts.csswg.org/filter-effects-2/)；本次结论以本机上述对照像素为依据，不将外部问题报告当作本机故障诊断。

前端 typecheck/build、Rust `cargo check --examples --locked`、纯逻辑 7/7 通过；未使用本机无法运行的 `cargo test`。工作台回归覆盖 1024/1360px、账户表单、人民币月均换算、消费历史、CSV、实际单价、模型对比、96 次独立调用散点和任务状态。圆角补齐后重新通过动效、实底回退、CSS 折射以及 520 项悬停/焦点可读性检查。

浏览器、解包程序及 `D:\Quota` 实际安装版均通过十组主题/明暗的透明像素检查，单次合成 Alpha 误差全部为 0。悬停、点击、移出时，工具栏中心与四角外侧像素差均为 0；交互高光开启后有圆角，移出后归零。原生窗口报告浮动状态，WebView 外框圆角为 14px，四角 Alpha 均为 0。
