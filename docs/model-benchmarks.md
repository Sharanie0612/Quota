# 模型榜单与数值口径

当前算法标识：`publisher-benchmarks/2.0`，自 1.0.2801 起使用。1.0.2800 的“五维分位合成分”已停用，其历史文档仅保留审计记录。

## 上一版的问题

- 先把约二十个交集型号的每个分项变成分位数，抹去了原始差距；参考型号的增减会改变既有模型的分数。
- 同一模型的不同分项分别取各推理档位的最大值，可能拼出实际不存在的配置。
- 把不同任务类型归为五个同名维度后等权平均，没有足够依据支持这些映射与权重。
- 官网结果只覆盖部分型号，20% 的人为混合权重产生了不对称影响。
- 先前测试主要覆盖数学自洽与渲染，不足以证明测评口径有效，也没有逐条核对真实 WebView 中的显示值。

例如本轮 AA 数据的 Opus 5.5 指数为 58.4060，高于 Astra 的 56.8539。旧组合分却给出相反顺序。多榜可以存在合理分歧，但原始成绩、组合名次和性能分不能混为一个数。

## AA 原始指数榜

[AA 模型榜](https://artificialanalysis.ai/leaderboards/models)中的 Intelligence Index v5 原始数值直接用于主榜，不再转换成 Quota 百分位或重算五维分数。

默认每个型号选择 **完整配置的公开综合指数最高者**。只从某一条配置中选择原始指数、分项和成本，绝不逐分项拼接。例如 Fable 5.1 的 Xhigh 指数可能高于 Max；默认采用 Xhigh 时会明确标出，不称它是 Max。

用户也可以选择 Low、Medium、High、Xhigh、Max、Reasoning 或 Non-reasoning。未发布该档位的型号不以其他配置替代。默认回退、防护、工具等条件保留在配置与原始记录中。

配置通过 AA 原始 slug 关联，`profileId` 同时保存在指数与每一条分项中。型号、日期、尺寸和未知变体仍严格保留。主榜每型号一条；效率图保留每个公开配置的单独点。

AA v5 本身采用四个 25% 的官方分类，具体内部指标与归一化见 [AA 方法](https://artificialanalysis.ai/methodology/intelligence-benchmarking)。Quota 不再以自己的权重替换它；尤其不能拿当前公开 Elo 重新推算可能使用冻结 Elo 的历史指数。MMMU-Pro 等附加测评可在分项中展示，不表示它被纳入 AA 综合指数。

## LiveBench 原始综合分

读取 [LiveBench](https://livebench.ai/)当前发布的 `table.csv` 与 `categories.json`，按该版本页面使用的类别权重计算。

20261025 版本的 `_overall_weights` 为：长程任务 2，编程 1.5，设计 1.5，未特别声明的推理、浏览、数据分析和研究各为 1。七项齐全时：

```text
Overall = (2×LongAgentic + Reasoning + 1.5×Coding + Browser
           + DataAnalysis + Research + 1.5×Design) / 9
```

空值和 `n/a` 从加权分母移除；已公开的 0 保持为 0。重复记录不增加权重。未测全的记录显示覆盖情况，不能进入跨榜共识。

官网某些旧 `notes.json` 的“各项等权”文案与当前分类配置不同。本轮同时核对了当前官网静态前端对 `_overall_weights` 的处理和加权函数，采用实际页面规则；没有执行第三方脚本。公开夹具和哈希由 `audit-benchmark-sources.py` 保存，权重随缓存与来源版本一起记录。

以 Fable 5.1 为例，七项成绩 77.9、91.7、97.7、89.8、80.3、82.0、83.4 的加权和为 771.25，综合分为 85.6944，显示为 **85.69**。它与 AA 的 49.67 属于不同测评尺度，不能直接平均成一个性能分。

## 跨榜共识：平均名次

共识是单独的排序参考，数值表示名次，越低越好，不是答对率、统一能力分或置信度。

1. 取同时拥有 AA 当前完整指数和 LiveBench 当前全部类别成绩的精确型号交集 `C`；至少 5 款才形成共识。单一平台已测的型号仍显示在各自原始榜中。
2. 在相同的交集 `C` 内，分别按 AA 和 LiveBench 的完整综合分排序。相同原分使用平均名次，例如占第 2、3 位时均为 2.5。
3. `共识平均名次 = (AA同池名次 + LiveBench同池名次) / 2`，按升序排列。相同平均名次并列，不以厂商、价格或某个单项偷偷打破并列。
4. 卡片明确标“同池 AA / LB 名次”。同池名次与源站全部型号中的名次可能不同；原始分榜保留全榜名次。

本轮 19 个型号符合条件。Opus 5.5 的同池名次为 AA 第 1、LiveBench 第 3，平均为 2；Astra 为第 2、第 2，平均也为 2，所以**共识榜并列第一**。这不改变 AA 原榜 Opus 第一、Astra 第二的事实。

各源站的任务、最高配置、工具和回退仍可能不同。共识只汇总它们的排序意见，不宣称同预算测试，也不隐去两个榜的分歧。源数据版本变动后必须保留版本和时间，不能将不同时期结果伪装成同一轮测评。

## 等级与能力图

S/A/B/C/D 只表示当前完整榜单的名次分层：前 10%、10–30%、30–60%、60–85%、85% 后。小样本边界向上取整，并列不拆开；分层不改变原始分数。搜索、厂商筛选不重新归一或重新编号。

能力图显示同一配置、同一具体测评的原始成绩。百分比和 Elo 保留各自单位与坐标，缺失用破折号。共识视图列出两个平台的原始综合分，不合并成同一条性能柱。

效率图继续使用同一 AA 配置的原始指数与美元/任务，保留推理档位和 Pareto 边界；API 每百万 Token 报价仍来自厂商官方价格库。

## 官网与架构

官网报告保留出处、核实时间、精确型号、工具与配置，用于独立对照，不以任意权重加入主榜或共识。相同测评名称下的不同 harness、不同预算和回退条件不能直接混算。

Quota 独立维护来源适配、公开记录、完整配置、原始榜单与共识计算。AITier 只作为展示参考，不是任何新分数或名次的运行依赖。参考 [LiveBench 官方代码](https://github.com/LiveBench/LiveBench/blob/main/livebench/show_livebench_result.py)的分类聚合，以及 [Arena Rank](https://github.com/lmarena/arena-rank)对原始对战数据的要求；没有票据时不拟合或宣称 Elo / Bradley–Terry 排名。

数据 schema 2 使用本机 `ai-benchmarks-v2.json`。旧 `ai-benchmarks-v1.json` 保留以支持回退，但不参与新榜单。来源版本或表结构不明确时保留上次成功数据并提示；每日公开数据与官方价格检查仍可在设置关闭。

## 验证与复现

```powershell
python scripts/audit-benchmark-sources.py
cd src-tauri
cargo run --release --example benchmark_checks -- --fixtures --live
# 人工审查后更新内置公开快照：再加 --write-seed
```

- `benchmark-golden.json` 是独立的源站预期值，包含四个 AA 公开指数与当前全部 31 个 LiveBench 综合分。数学边界测试另外覆盖整套配置、单源、重复、顺序、缺失、官网隔离、新型号不改写既有原分等。
- `reconciliation.json` 保存本轮预期值、实际值和配置 ID。所有 AA 主榜条目另逐一检查与其来源 profile 的原始指数完全一致。
- 浏览器检查每一张卡片的分数、名次与配置 ID，覆盖三榜、档位、分项和明暗模式。
- `check-benchmark-ui.ps1` 启动真实打包 WebView，读取实际渲染的三榜文本并与 Rust 结果及独立黄金样本核对。运行目录隔离，账户为空、关闭采集与同步。升级验收加 `-CheckBenchmarks`。
