# 1.0.3402 原生标题栏与直角外框修复

2026-10-31，Windows 本地修复构建。展示版本与包版本均为 `1.0.3402`。

用户提供的 1.0.3401 桌面图显示，透明主窗口上方出现 Windows 经典标题栏和第二组窗口按钮，外侧还有白色直角边框。这属于原生窗口绘制层。上一轮 WebView 的透明度、高光和圆角像素检查没有覆盖这一层，不能据此判断这次问题已解决。用户图片包含个人桌面和用量信息，仅用于定位，没有放入仓库或测试资料。

## 实现

本机为 Windows 10 19045。修复前只读原生检查确认，主窗口客户区已经铺满整个窗口，WRY/WebView 子窗口没有标题栏样式；主窗口本身仍保留 `WS_CAPTION` 和 `WS_THICKFRAME`。当前 Tao 0.35.3 为缩放和 Snap 保留这些样式，激活路径仍会调用 Windows 默认窗口过程。

现在只在主窗口的 UI 线程安装子类过程：处理 `WM_NCPAINT` 和主题标题栏/边框绘制消息；`WM_NCACTIVATE` 继续交给 Tao 和系统默认过程，但使用禁止重画非客户区的参数。最小化及其他消息正常转发，不改写窗口大小计算和命中测试。窗口销毁时移除子类并释放它持有的状态。

主窗口先隐藏，安装保护和圆角后再显示，避免首次显示时缓存系统标题栏。保护不可用时保留可读的实底界面，不启用原生 Acrylic。任务悬浮窗不套用此保护或整窗 Acrylic。安装向导显式设为可见，避免继承主窗口隐藏配置。

区域更新只在窗口所属线程执行。缓存命中后还会核对实际原生区域：浮动窗口须保留完整圆角，贴边/最大化须没有自定义曲线区域或仅有系统矩形裁剪，避免缓存声称直角而原生仍保留圆角。隔离验收也在窗口线程上连续执行更新和区域读取，防止测试工作线程与窗口事件交错。

参考 Windows 官方的 [WM_NCACTIVATE 参数规则](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-ncactivate) 和 [WM_NCPAINT 绘制行为](https://learn.microsoft.com/en-us/windows/win32/gdi/wm-ncpaint)。[Tauri 的相关透明窗口标题栏报告](https://github.com/tauri-apps/tauri/issues/14764) 仅作为背景资料；本轮没有据此降级 WebView2，也不把上游历史报告当作本机修复后的视觉证据。

## 验证

前端 typecheck/build、Rust `cargo check --examples --locked`、纯逻辑 7/7 已通过，没有运行本机不可用的 `cargo test`。合成资料的工作台检查覆盖 1024/1360px、账户表单、人民币月均换算、历史消费、CSV、实际单价、模型分组和六维对比、96 次无连线速度散点及任务状态。

首次候选的原生检查确认保护已安装，拦截 15 次非客户区绘制和 24 次主题绘制，并安全转发 25 次激活；但在最大化形状检查失败，未安装交付。随后在同一候选的隔离运行中读取区域边界：浮动/还原为复杂圆角区，四个边界角点均在区域外；最大化为从 `(8,8)` 开始的矩形工作区裁剪，四角均在区域内。原检查仅依据外框 `(0,0)` 被排除而误判圆角。现改为结合区域类型和边界角点分类，并保留首次失败及诊断资料，没有修改产品窗口形状逻辑。

第二个候选正确识别了最大化矩形裁剪，但贴边检查记录到“直角状态、圆角区域”的不一致，也未安装。最终实现增加上述实际区域核对和窗口线程约束；两次失败均保留，不算作完整验收通过。

最终候选 `candidate3` 的解包程序和实际安装版均通过四组玻璃开关/深浅色的隐藏、最小化及还原检查；实际激活转发计数由 1 增至 16，客户区与浮动窗口外框同宽同高、原点一致。独立原生探针确认保护已注册，完成至少 12 次非客户区绘制拦截、24 次主题绘制拦截及 24 次激活转发，缩放相关样式保留。浮动、最大化、全屏、贴边及还原五种区域全部通过，贴边不再残留复杂圆角区，浮动和还原保持圆角。

两个程序分别通过十组主题/明暗的透明图层像素检查，Alpha 合成误差均为 0；玻璃关闭和模拟高对比度可恢复实底。真实 Rust 命令与打包 WebView 的回归覆盖人民币月均换算、消费历史、实际单价、五种主题、交互高光、焦点恢复和三种窗口尺寸下的高光定位、逐次调用散点、模型分组，以及两项合成运行任务和四组过期任务窗响应。WebView 圆角外侧透明；任务窗画布保持 324×276。DPI、系统配色和高对比度使用模拟，未改动 Windows 系统设置。
