# 输出速度

当前页面展示Codex的**已完成输出速度趋势**，默认近7天。贴边悬浮窗只展示运行任务、型号、开始时间、经过时长及今日/累计Token，不再放置速度或接收片段计数。现有本机JSONL包含响应结束后的用量、文本输出起止时间，没有逐Token计数；读取频率不等于测速分辨率。

官方[App Server事件文档](https://learn.chatgpt.com/docs/app-server#item-deltas)区分消息增量与完成事件；[可观测性文档](https://learn.chatgpt.com/docs/config-file/config-advanced#observability-and-telemetry)说明用量计数随`response.completed`提供。现有日志适配器不连接或接管Codex正在使用的App Server，也不根据字符数估算Token。

## 读取与测速分别处理

- 本机`LocalReader`以1秒为目标周期检查近期文件和今天的新会话，按原游标读取新增完整JSONL行。非常规布局和归档通过15秒目录发现及正常历史采集补齐。
- 本机读取拥有独立后台任务，仅与完整采集的**本机游标读取**互斥。SSH、目录同步不持有这把本机锁；数据库事务仍然原子提交，失败可重试。
- 读取时间只用于来源健康状态。测速始终使用响应原始时间，不用轮询间隔作为分母，不把旧记录移动到当前时间。
- 任务开始和结束只更新等待状态。仅有文本计时、没有完整用量，或最后一行尚未写完时不生成速度。源异常会持续显示，不能用一次空轮询清除错误。
- 前端合并活动更新通知与5秒兜底查询。慢请求不互相覆盖，不因轮询不断取消而永远无法显示；自动更新保留正在查看的时间点。
- 关闭自动采集同时暂停本机和SSH读取。目录同步维持原周期；远程记录随其实际采集与同步到达，不标为本机实时记录。

## 计算与时间维度

### 悬浮窗任务与兼容元数据

1.0.3200按列表展示正在运行的本机任务，同型号任务通过开始时间区分。暂停、读取延迟或异常时清除工作列表的活跃显示，保留短状态。1.0.3100提供的本轮均速、已确认输出与可选接收片段元数据保留接口兼容，但不再展示于悬浮窗。

状态随本机读取更新，超过 6 秒未确认即显示延迟，暂停、未配置来源或读取异常时不沿用旧任务速度。超过 15 分钟没有事件的任务不继续显示为活跃；最多展示最近 16 个任务。任务状态是本机运行信息，不随用量包同步。

当本机 Codex 提供兼容的 `logs_2.sqlite` 时，以只读连接统计最近 5 秒 `item/agentMessage/delta` 通知的数量和最近时间。只返回计数与时间，不读取正文结果、不写回来源库，也不保存对话片段。文件缺失、结构不兼容或暂时锁定时退回任务状态和已完成输出统计。

该信号属于**本机 Codex 全局**，没有可靠的模型归属，不会记入所选任务 Token。片段大小不固定，不能换算 tokens/s；暂停自动采集时停止检查该来源。

### 已完成响应

```text
非推理输出Token = usage.output_tokens − usage.reasoning_output_tokens
一条输出的速度 = 非推理输出Token × 1000 / 输出时长毫秒
时段平均速度 = 该时段有效输出Token总数 × 1000 / 输出时长总和毫秒
```

例如200 Token用2秒、100 Token用0.5秒：均值为`300 / 2.5 = 120 tokens/s`，不能将100和200直接平均得到150。

`token_usage_record`的用量与同一次响应的`AgentMessage`起止时间关联。重叠输出片段取区间并集，排除工具调用、思考、等待、缺失计时或用量不匹配。有效样本至少64个非推理输出Token、500毫秒。该客户端观测值包含接收链路和缓冲的影响，不等于服务端引擎解码速度。

1.0.3300起图表使用**每次响应的完成时间与单次速度**，一条有效记录对应一个散点。不连线、不均摊长响应、不把时间桶均值当作调用。重复时间的调用仍保留独立ID；完全重合的点可用方向键或记录表逐条查看。横轴聚焦有调用的区间，单样本居中，纵轴从零开始。

页面默认近7天；顶部显示加权均值、最近一次速度和有效输出数量。全部筛选样本通过Canvas绘制，避免大量SVG节点；悬停或方向键查看型号、Token和耗时。记录首屏24条，继续展开可查看全部筛选历史。旧时间桶接口字段保留兼容，当前图表不使用。

## 实时能力核实（2026-10-30）

[Codex App Server](https://learn.chatgpt.com/docs/app-server)区分文本增量`item/agentMessage/delta`与用量更新`thread/tokenUsage/updated`。文本增量没有逐Token计数，不能将一条通知当作一个Token。[官方遥测说明](https://learn.chatgpt.com/docs/agent-approvals-security)明确Token计数随`response.completed`提供。

本机只读抽查两份近期JSONL的类型与字段，6次`token_usage_record`对应6次`token_count`，没有连续的生成中Token计数；未输出正文、工具参数或凭据。运行中的App Server未显式配置WebSocket监听，默认stdio属于现有客户端。因此，本版的只读日志通道不能准确展示生成中的实时tokens/s；这是当前接入方式的边界，不是断言所有Codex集成均不具备流式能力。

产品采用已完成响应趋势，运行状态保留在悬浮窗。后续来源若提供可归属到响应的累计Token计数和时间戳，可另行增加经验证的实时适配。

## 保存与同步

`Metric.speed`继续附在原Token事件上，不建立另一套用量账本，不修改原事件ID和同步协议。只保存摘要标识、输出起止、时长、Token数量和原有方法版本。游标新增任务活跃状态和最后事件时间，不保存正文、工具参数或凭据。

旧记录没有计时时不补造速度；旧包重放不能抹掉已有速度元数据。首次速度适配升级的历史回填机制保持兼容。本机快速读取与完整读取共用游标、原子事务与去重，目录同步仍通过原outbox传递。

SSH继续按字段白名单只读提取，未选择设备不采集。取消设备后保留本机历史，但从统计视图中排除；其他harness尚未接入此页。速度索引限定已有`speed`事件和时间范围，避免每秒遍历整个用量账本。

## 验证

`output_speed_checks`覆盖完整逐次调用列表、24条之外的历史、筛选、加权均值、兼容时间桶、原始记录对账、暂停恢复、完整/快速采集兼容、半截日志、未完成响应、任务指标、可选流式信号的时间窗口与结构回退、计时缺失、旧包重放、排除设备及隐私。真实日志可只读回放到新建隔离资料库：

```text
cargo run --release --example output_speed_checks
cargo run --release --example output_speed_checks -- <Codex数据目录>
```

`check-output-speed-incremental.ps1`使用打包程序与合成日志：完整采集设为900秒，外部追加任务状态、缺少结尾换行的记录与完整用量，直接测量**文件写入到新速度记录入库的延迟**；核对等待阶段不产生样本、半行重试、加权均值和Token总量。它测量读取延迟，不把它称为流式测速精度。

浏览器检查另行验证自动呈现、慢请求合并、悬停稳定、均值粒度与记录核对、空数据、无计时、暂停和等待状态。真实SSH、真实云端双机和macOS安装需要实机验证。
