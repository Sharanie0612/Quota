# 输出速度

当前页面展示Codex的**已完成输出速度**和按时间统计的均值。现有本机JSONL包含响应结束后的用量、文本输出起止时间，没有逐Token计数。读取更频繁不会增加测速分辨率；本页不声称能测量生成中的流式tokens/s。

官方[App Server事件文档](https://learn.chatgpt.com/docs/app-server#item-deltas)区分消息增量与完成事件；[可观测性文档](https://learn.chatgpt.com/docs/config-file/config-advanced#observability-and-telemetry)说明用量计数随`response.completed`提供。现有日志适配器不连接或接管Codex正在使用的App Server，也不根据字符数估算Token。

## 读取与测速分别处理

- 本机`LocalReader`以1秒为目标周期检查近期文件和今天的新会话，按原游标读取新增完整JSONL行。非常规布局和归档通过15秒目录发现及正常历史采集补齐。
- 本机读取拥有独立后台任务，仅与完整采集的**本机游标读取**互斥。SSH、目录同步不持有这把本机锁；数据库事务仍然原子提交，失败可重试。
- 读取时间只用于来源健康状态。测速始终使用响应原始时间，不用轮询间隔作为分母，不把旧记录移动到当前时间。
- 任务开始和结束只更新等待状态。仅有文本计时、没有完整用量，或最后一行尚未写完时不生成速度。源异常会持续显示，不能用一次空轮询清除错误。
- 前端合并事件通知与每秒查询。慢请求不互相覆盖，不因轮询不断取消而永远无法显示；自动更新保留正在查看的时间点。
- 关闭自动采集同时暂停本机和SSH读取。目录同步维持原周期；远程记录随其实际采集与同步到达，不标为本机实时记录。

## 计算与时间维度

```text
非推理输出Token = usage.output_tokens − usage.reasoning_output_tokens
一条输出的速度 = 非推理输出Token × 1000 / 输出时长毫秒
时段平均速度 = 该时段有效输出Token总数 × 1000 / 输出时长总和毫秒
```

例如200 Token用2秒、100 Token用0.5秒：均值为`300 / 2.5 = 120 tokens/s`，不能将100和200直接平均得到150。

`token_usage_record`的用量与同一次响应的`AgentMessage`起止时间关联。重叠输出片段取区间并集，排除工具调用、思考、等待、缺失计时或用量不匹配。有效样本至少64个非推理输出Token、500毫秒。该客户端观测值包含接收链路和缓冲的影响，不等于服务端引擎解码速度。

图表按**响应完成时间**归入当地日历时间桶。它回答“这个时段完成的输出平均多快”，不回答“这10秒内实际生成了多少Token”。不将一条长响应均匀摊入多个时间桶冒充真实流式测量。没有记录的时段留空，相邻时间桶以外的点不连线，不平滑补点。

| 时间范围 | 默认均值粒度 | 可选粒度 |
| --- | --- | --- |
| 近30分钟 | 10秒 | 10秒、1分钟、5分钟 |
| 今天 | 1小时 | 1分钟、5分钟、1小时 |
| 7天 | 1天 | 1小时、6小时、1天 |
| 30天、全部 | 1天 | 6小时、1天 |

页面默认今天；同时显示时段均值、最近一次已完成输出及其型号和时间、有效输出数量。未纳入计时的用量单独计数。趋势与“记录”切换共用同一个范围；记录页可核对最近24条响应的完成时间、Token数、耗时和速度。模型汇总逐个计算同一时段均值，点击筛选。

## 保存与同步

`Metric.speed`继续附在原Token事件上，不建立另一套用量账本，不修改原事件ID和同步协议。只保存摘要标识、输出起止、时长、Token数量和原有方法版本。游标新增任务活跃状态和最后事件时间，不保存正文、工具参数或凭据。

旧记录没有计时时不补造速度；旧包重放不能抹掉已有速度元数据。首次速度适配升级的历史回填机制保持兼容。本机快速读取与完整读取共用游标、原子事务与去重，目录同步仍通过原outbox传递。

SSH继续按字段白名单只读提取，未选择设备不采集。取消设备后保留本机历史，但从统计视图中排除；其他harness尚未接入此页。速度索引限定已有`speed`事件和时间范围，避免每秒遍历整个用量账本。

## 验证

`output_speed_checks`覆盖加权均值、时间桶、原始记录对账、暂停恢复、完整/快速采集兼容、半截日志、未完成响应、计时缺失、旧包重放、排除设备及隐私。真实日志可只读回放到新建隔离资料库：

```text
cargo run --release --example output_speed_checks
cargo run --release --example output_speed_checks -- <Codex数据目录>
```

`check-output-speed-incremental.ps1`使用打包程序与合成日志：完整采集设为900秒，外部追加任务状态、缺少结尾换行的记录与完整用量，直接测量**文件写入到新速度记录入库的延迟**；核对等待阶段不产生样本、半行重试、加权均值和Token总量。它测量读取延迟，不把它称为流式测速精度。

浏览器检查另行验证自动呈现、慢请求合并、悬停稳定、均值粒度与记录核对、空数据、无计时、暂停和等待状态。真实SSH、真实云端双机和macOS安装需要实机验证。
